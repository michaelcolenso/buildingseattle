# SEO audit and remediation — September 25, 2026

## Scope

Live crawl of `https://buildingseattle.com` (primary routes, 30 randomly
sampled sitemap URLs, detail and error pages, six child sitemaps) plus a
source review of `worker.js`, combined with the automated production monitor
(`node scripts/check_seo_health.mjs https://buildingseattle.com`).

Baseline before this change: 235/235 monitor checks passed, so every finding
below came from crawl evidence rather than a failing check.

## Findings and fixes

1. **Address titles overflowed SERP truncation (~11,700 URLs).** Live titles
   ran 100–135 characters because the featured permit descriptor was
   concatenated into the title with no budget. Address titles now spend at most
   62 characters (`ADDRESS_TITLE_MAX` in `renderAddressPage`): the address and
   `| Building Seattle` suffix always ship, the source-backed descriptor ships
   only when it fits, and the incompatible `| Seattle Construction` brand
   variant is gone.
2. **`/about` was orphaned.** No page linked to it (sitemap and `llms.txt` only).
   `renderFooter` and the homepage footer now link `/about` (plus the API from
   `renderFooter`), and the monitor asserts homepage link coverage.
3. **The homepage bypassed the HTML edge cache and the discovery `Link`
   header.** `site_worker.js` intercepted `/` outside `withHtmlEdgeCache` and
   built its own security headers. The task-first homepage now lives in
   `worker.js`, `wrangler.toml` points `main` at `worker.js`, and
   `site_worker.js` is deleted, so `/` is cached and advertises
   sitemap/llms/api-catalog like every other page.
4. **Two homepage implementations, one live.** The obsolete homepage template,
   its lead-capture modal, `renderHomeGraphSection`, `homeMarkdown`, and the
   unused inline WebMCP script were removed. Homepage rendering is a single
   source of truth, and a test fails if the retired markup returns.
5. **`/about`, `/data`, and `/api-docs` had incomplete head/schema.** All three
   now ship `index,follow,max-image-preview:large`, canonical, Open Graph with
   dimensions/alt, `twitter:*` with `summary_large_image`, and JSON-LD
   (`AboutPage`/`Organization`, `Dataset`/`Product`, `TechArticle`/`WebAPI`)
   with breadcrumbs. Descriptions were trimmed under 160 characters, and
   `/api-docs` gained `h2` sections so heading levels no longer skip h1 → h3.
6. **Neighborhood and housing pages under-declared schema.**
   `/neighborhood/{slug}` now publishes `CollectionPage` + `Place` +
   `BreadcrumbList` (visible breadcrumb aligned to the neighborhood hub), and
   `/insights/housing` gained a breadcrumb alongside its `Dataset`.
7. **Error responses canonicalized to the homepage.** The shared 404 template
   is `noindex` with no cross-page canonical, and the monitor probes a random
   not-found URL to prove it stays a real 404.
8. **`/permits` used `twitter:card: summary` with a 1200×630 image**, which is
   now `summary_large_image`.
9. **Smaller items.** `/api-docs` added to `SITEMAP_STATIC_PATHS`; the stale
   committed `seo-health-report.json` removed and git-ignored; `HTML_CACHE_VERSION`
   bumped to `v4`; a `Skip to content` link and `#main-content` landmark added
   to the shared templates; address meta descriptions no longer repeat
   “Seattle” for addresses that already contain it.

## Verification

- `node --check worker.js`, `node --test tests/*.test.js` (7/7 files pass,
  including the new `tests/homepage.test.js` and the extended
  `tests/worker.test.js` / `tests/seo_health.test.js` coverage).
- `npx wrangler deploy --dry-run` bundles `worker.js` as the Worker entry with
  the D1 and Email bindings.
- Homepage HTML rendered from `worker.js` was diffed against the pre-change
  production render produced by `site_worker.js` under an identical stub
  environment: the only differences are the intended metadata, skip-link, and
  footer-link additions.
- `/api/stats` and `/api/contractors` payloads are byte-identical to the
  pre-change production contract, so removing `site_worker.js` did not change
  the public API.
- The expanded monitor (now 261 checks: per-route title budgets, insight and
  neighborhood schema contracts, homepage link coverage, and a 404 probe) fails
  against the still-deployed build on exactly the four issues fixed above:
  `page-title-length` (address), `page-schema-type` (neighborhood),
  `homepage-link-coverage` (`/about`), and `notfound-no-canonical`.

## Open items that need a decision, not code

- **Thin entity pages:** ~12.2k project and ~11.7k address URLs versus ~14.8k
  permits; many entity pages restate a single permit. Indexing policy
  (threshold, enrichment, or consolidation) is a product decision.
- **`/.webmcp/bridge.js`:** a 47 KB module script is injected into `<head>` on
  every HTML response at the edge. Nothing in this repository serves or injects
  it, and other paths under that prefix return a bodyless `404` instead of this
  Worker's HTML 404 page — so it comes from a zone-level integration outside
  the repo. Confirm it is intentional.
- **Search Console baselines** (sitemap submission, indexed/discovered/excluded
  counts) still require property access and remain manual.
- **Editorial landing pages** for high-intent local themes remain a content
  roadmap item; the market-segment insight pages cover part of it.
